# Implementation plan toward an Inria Chile repository

## Phase 0 - Repository contract and governance

**Implemented now:** package metadata, `uv`, Hydra composition, path policy, external-artifact manifest validation, provenance capture, report consolidation, CPU-fast tests, atomic Zenodo ingestion, streaming inventories, deterministic bucket indices and a bounded-memory unigene registry builder.

**Before GitHub publication:** choose the final repository name with Inria Chile, confirm Apache-2.0 compatibility, add governance files, name maintainers, resolve model/data licenses and create a private review repository.

## Phase 1 - Data import and canonical registries

Atomic Zenodo downloads with size and MD5/SHA-256 verification and compressed streaming inventories are implemented. The unigene registry builder is migrated and tested. Remaining work is to formalize versioned ORF, AGC, sample and environmental registries, preserve exclusion ledgers and reproduce frozen full-catalog checksums.

## Phase 2 - Ecological harmonization

Separate measured, reconstructed and climatological variables. Encode units, depth, fraction, station, water mass and uncertainty. Add sample-group-aware tests and explicit missingness policies. Reproduce frozen ecology summaries from the internal reports.

## Phase 3 - Benchmark and classical baselines

Migrate translation, MMseqs clustering, immutable splits, codon/GC/length features and nearest-neighbor baselines. Fit all transformations on TRAIN only. Reproduce the six task tables and paired group-bootstrap confidence intervals.

## Phase 4 - Foundation-model representations

Create backend interfaces for GenomeOcean, ESM2 and ESM3. Pin model revisions, pooling, truncation, precision and sequence hashes. Support resumable shards and CPU-only fixture backends. ESM3 structure remains interpretation-only unless a future preregistered gate changes that decision.

## Phase 5 - Multimodal learning and open-set evaluation

Migrate classifiers, dimension-controlled fusion, ecology alignment, shuffled controls, calibration, abstention and domain-shift evaluation. Make task, representation and seed matrices Hydra sweeps. Export long-form metrics and group-bootstrap replicates.

## Phase 6 - Functional hypothesis generation

Implement masked-known retrieval, function-held-out tasks and evidence tiers combining representation, motifs/domains, genomic context, co-abundance, taxonomy and ecology. Prevent the word “annotation” in candidate exports unless a separate validation field supports it.

## Phase 7 - Release and archival

Run CI, security and license scans; build documentation; publish a tagged GitHub release; mint a Zenodo DOI for code and permitted small artifacts; archive external checksums; prepare the INACH reproduction guide and public Atlas data dictionary.

## Definition of done

- a fresh clone passes `uv sync --extra dev && uv run pytest -q`;
- every published table is generated by a documented command from a resolved Hydra configuration;
- no committed path points to a personal home or Grid'5000 mount;
- all transformations are train-only where applicable;
- all stochastic stages record seeds and deterministic limitations;
- every external input and output has an immutable identifier and checksum;
- every claim in the paper/proposal maps to a result table and testable rule;
- independent Antarctic transfer is included before scientific release.
